# Mobile Layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the site use the phone layout that currently exists only as a static mock on `mobile-views.html`, then delete that page.

**Architecture:** A native `<details>` drawer replaces the horizontal nav below 900px. It lives in the shared `ntgocSiteHeader` chunk and is propagated to every page by `npm run shell`. Its link list duplicates the desktop nav's, and a new `npm run lint` rule fails the build if the two drift apart. `ntgoc-enhance.js` adds Escape, outside-click and scroll-lock on top, but the drawer works without it.

**Tech Stack:** Hand-edited static HTML, one hand-edited stylesheet (`assets/css/components.css`), one vanilla JS file, Node audit tools (`lint`, `snap`, `audit:a11y`, `audit:reflow`) run through npm scripts. No framework, no build step, no dependencies in the site itself.

**Design spec:** `docs/superpowers/specs/2026-08-09-mobile-layout-design.md`

## Task 1: The parity lint rule

The drawer and the desktop nav are the same links written twice. This rule is
what stops one rotting while the other is maintained. It is written **first**, so
it fails before the drawer exists and passes once the drawer is right.

**Files:**
- Modify: `tools/lint.mjs` — insert after the block that ends at line 315 (rule 6b, "Every class used in the markup is actually defined"), before the comment banner for rule 7

- [ ] **Step 1: Write the rule**

Insert this immediately before the `* 7. Assets referenced from the markup actually exist` banner:

```js
/* ------------------------------------------------------------------ *
 * 6c. The drawer and the desktop nav must offer the same links
 *
 * Below 900px the horizontal nav is hidden and the <details> drawer is the
 * whole navigation. The two lists are the same links written twice, and
 * nothing but this check stops one being updated while the other quietly
 * rots — which on a phone means a page nobody can reach.
 *
 * Sets, not sequences: the drawer leads with "Plan a visit" the way the
 * mobile design does, and that is deliberate. .ntgoc-drawer__utility and
 * .ntgoc-drawer__service are drawer-only and are not compared.
 * ------------------------------------------------------------------ */
{
  /* Pull the hrefs out of the element carrying `cls`, by walking from its
     opening tag to the matching close and counting nesting on the way. A
     plain non-greedy match would stop at the first </div> instead. */
  const hrefsIn = (body, cls) => {
    const opener = new RegExp(
      `<(\\w+)[^>]*\\sclass="[^"]*(?<![\\w-])${cls}(?![\\w-])[^"]*"[^>]*>`);
    const m = body.match(opener);
    if (!m) return null;

    const start = m.index;
    let depth = 0, end = -1;
    for (const t of body.matchAll(new RegExp(`<(/?)${m[1]}\\b[^>]*>`, 'g'))) {
      if (t.index < start) continue;
      depth += t[1] ? -1 : 1;
      if (depth === 0) { end = t.index; break; }
    }
    if (end === -1) return null;

    return new Set([...body.slice(start, end).matchAll(/<a\s+href="([^"]+)"/g)]
      .map(x => x[1]));
  };

  for (const rel of PAGES) {
    const body = read(rel);
    const nav = hrefsIn(body, 'ntgoc-nav');
    const drawer = hrefsIn(body, 'ntgoc-drawer__list');
    if (!nav && !drawer) continue;
    if (!drawer) {
      err('nav-drawer-parity', rel,
        'has a desktop nav but no .ntgoc-drawer__list — below 900px there is no navigation at all');
      continue;
    }
    if (!nav) {
      err('nav-drawer-parity', rel, 'has a .ntgoc-drawer__list but no .ntgoc-nav');
      continue;
    }
    for (const h of [...nav].filter(h => !drawer.has(h))) {
      err('nav-drawer-parity', rel, `"${h}" is in the desktop nav but missing from the drawer`);
    }
    for (const h of [...drawer].filter(h => !nav.has(h))) {
      err('nav-drawer-parity', rel, `"${h}" is in the drawer but missing from the desktop nav`);
    }
  }
}
```

Note the lookarounds `(?<![\w-])` / `(?![\w-])` rather than `\b`. A `\b` after
`ntgoc-nav` would also match inside `ntgoc-nav-link`, because `-` is not a word
character — the rule would then read the wrong element and pass for the wrong
reason.

- [ ] **Step 2: Append the drawer IIFE**

At the end of the file, after the existing `}());`:

```js

/* ------------------------------------------------------------------------
 * The phone navigation drawer.
 *
 * The drawer is a native <details>, so it opens and closes without any of
 * this. What follows is the polish a hand-built menu would need anyway:
 * Escape closes it, so does a click outside or a tap on any link, and the
 * page behind it stops scrolling while it is open.
 *
 * All of it is optional. Skip this file in EVO and the drawer still works.
 * ---------------------------------------------------------------------- */
(function () {
  'use strict';

  var drawer = document.querySelector('[data-ntgoc-drawer]');
  if (!drawer) return;

  var toggle = drawer.querySelector('summary');
  if (!toggle) return;

  drawer.addEventListener('toggle', function () {
    if (drawer.open) {
      document.body.className += ' ntgoc-scroll-locked';
    } else {
      document.body.className = document.body.className
        .replace(/\s*ntgoc-scroll-locked/g, '');
    }
  });

  document.addEventListener('keydown', function (event) {
    if (event.key !== 'Escape' || !drawer.open) return;
    drawer.open = false;
    toggle.focus();
  });

  /* A click anywhere outside the drawer closes it. Registered on the
     document, so it also catches taps on the page behind the panel. */
  document.addEventListener('click', function (event) {
    if (!drawer.open || drawer.contains(event.target)) return;
    drawer.open = false;
  });

  /* Following a link inside the drawer should not leave it hanging open
     behind the next page's paint. */
  drawer.addEventListener('click', function (event) {
    for (var el = event.target; el && el !== drawer; el = el.parentNode) {
      if (el.tagName === 'A') { drawer.open = false; return; }
    }
  });
}());
```

`className` string manipulation rather than `classList.toggle(name, force)` —
the two-argument form of `toggle` is unsupported in older browsers, and the rest
of this file is written to the same conservative standard (`var`, no arrow
functions) because it has to survive being pasted into a CMS template of unknown
vintage.

## Notes for whoever executes this

**Another session may be working in this repo.** Before pushing or merging,
`git log --oneline` — a concurrent session's `git add -A` may already have
committed some of this under its own message. Verify with the log, not with
`git status`.

**Never pipe a build into `tail` and read the exit code.** `npm run check | tail`
reports `tail`'s status, not the check's. The commands above put `| tail` or
`| head` only on runs whose output is being read for content, never as the basis
for a pass/fail claim. When you need the verdict, run the command bare.

**`npm run snap -- --update` is not a fix.** It records whatever is on screen as
correct. Every task that calls for it calls for reading the deltas first, and
that ordering is not optional — it is the only check in this repo that sees
layout at all.
